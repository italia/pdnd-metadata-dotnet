# Diagrams

Four figures, each in a light and a dark variant, all generated by `build.py`.

| Figure | Shows | Used in |
|--------|-------|---------|
| `architecture` | Where the library sits relative to PDND, the edge, and your own validation | README |
| `pipeline` | Headers in, canonical snapshot out, and the boundary the library does not cross | README, specification |
| `keyspace` | The four families of canonical keys and their sources | README |
| `conformance` | The specification as a contract with independent implementations | README |

## Regenerating

```
python3 assets/diagrams/build.py
```

Everything is produced from one file so that grid, palette, stroke weight, and typography cannot
drift between figures. Edit `build.py`, never the SVG output.

## Rules the figures follow

- Eight pixel grid. Every coordinate is a multiple of four.
- One accent colour, one neutral ramp, and one semantic colour used sparingly for the boundary.
- Three type sizes: eyebrow at 9.5 uppercase and tracked, title at 13 medium, caption at 10.5.
- Identifiers in monospace, prose in sans, never mixed inside one string.
- Section labels sit outside their container.
- A solid border means the request passes through it. A dashed border means it is out of scope.

## Why hand-written SVG

No build tooling, no external service, and no binary output. The figures are diffable, so a
change to one shows up in review as a change to that shape rather than as an opaque new file.
